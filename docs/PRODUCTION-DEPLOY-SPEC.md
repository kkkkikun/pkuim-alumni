# 正式发布服务器规格建议（Production Server Spec）

> 面向对象：项目负责人（要下单买机器的人）。
> 结论先说：**买一台阿里云轻量应用服务器「通用型 4核8G / 70GiB / 200Mbps 不限流量 / 呼和浩特」，
> 新用户价约 ¥1159/年，单机跑全套 7 个容器。**
> 现有那台 `8.160.116.34`（2核1G）**不能**用作生产，只能继续当边缘 + 隧道。
>
> 本文所有数字都来自实测或厂商当日公开价，来源逐条标注在文末。

## 一、为什么是这个规格：先看实测基线

选型不能凭感觉，所以先量了当前生产栈的真实占用（在校园机 `sqserver` 上，
`docker stats --no-stream` + `information_schema` 实测，2026-11-18）：

| 容器 | 实际内存占用 | 备注 |
|---|---|---|
| `nmg-api` | **90 MB** | NestJS 业务 API |
| `nmg-worker` | **33 MB** | BullMQ 常驻 |
| `nmg-nginx` | 148 MB | 边缘反代 |
| `nmg-minio` | 122 MB | 对象存储（生产会换成 OSS/COS） |
| `nmg-redis` | 8 MB | 缓存 + 队列 |
| `nmg-mysql` | **8.1 GB** | ⚠️ 其中 8 GB 是 `innodb_buffer_pool_size` 手工开的池，**不是数据量** |
| `nmg-admin-web` | 92 MB | Vue3 后台 |

**真实数据体量**：业务库 `nmg_alumni` 共 **33 张表、12.0 MB**（data + index）；
测试库 `nmg_alumni_test` 1.5 MB。测试库与业务库物理隔离 ✅。

> 关键结论：**业务库只有 12 MB**。这个系统是「小数据 + 中等并发」，
> 不是「大数据 + 高并发」。所以机器需求由**并发**决定，不由**数据量**决定。

### 由此推出的三个判断

1. **2核2G 一定不够。** 光 MySQL 池子调到合理值（512M~1G）就吃掉一半内存，
   再加 API/Worker/Nginx/Redis/Admin 共 ~500 MB、系统与 Docker 自身 ~800 MB，
   余量不足 400 MB —— 校庆活动报名那种瞬时并发会直接 OOM。
2. **4核8G 是舒适位。** 调优后整机常驻约 **2.5~3 GB**，留 5 GB 余量给
   并发峰值、备份、日志、发布时的镜像构建。**多出来的 4 GB 不是浪费，是不用熬夜扩容的余量。**
3. **带宽不是瓶颈，磁盘才是。** 图片会走对象存储（OSS/COS），API 只回 JSON；
   但 Docker 镜像 + DB 数据 + MinIO 临时文件 + 日志 + 本地备份都要占盘，
   70 GiB 系统盘要精打细算。

## 二、推荐方案（主方案）

### 阿里云轻量应用服务器 · 通用型 4核8G

| 项 | 规格 | 说明 |
|---|---|---|
| CPU / 内存 | **4 vCPU / 8 GiB** | 见上表实测推导 |
| 系统盘 | **70 GiB ESSD** | 见下方「磁盘要加盘」 |
| 公网带宽 | **200 Mbps 峰值，不限流量** | 2026 版轻量全系升级；图片走 OSS 后用不到 200M |
| 地域 | **cn-huhehaote（呼和浩特）** | 内蒙用户延迟最低；备案接入商与域名注册商一致 |
| 系统 | Ubuntu 24.04 LTS | 与现有阿里云边缘机一致，减少差异 |
| 预付费 | **包年 1 年**（可一次买 3 年更便宜） | 备案要求服务器已购买且满足时长 |
| 价格 | 目录价 ¥220/月；**新用户 ¥1159/年** | 4核16G 为 ¥1599/年；2核4G 为 ¥379/年 |

### 为什么选阿里云而不是腾讯云

现有路径已经铺在阿里云上了：**域名注册商（万网）= 备案接入商 = 现有边缘机厂商**。
换厂商意味着域名要么迁注册商、要么把备案接入商换掉 —— 多一道手续、多 1~2 周。

### 为什么选 4核8G 而不是 2核4G（¥379/年，便宜 3 倍）

省 ¥780/年 换来的代价：
- 内存余量从 ~1.3 GB 压到 ~0.4 GB，**校庆峰值有 OOM 风险**；
- **阿里云轻量是套餐化架构，不支持在线升降配** —— 买小了想改，只能退订重买，
  期间要迁数据、换 IP、重配备案关联，风险和 downtime 远不止 ¥780；
- 2核4G 起步就意味着正式发布当天就带着隐患。

> 反过来，**腾讯云**的 2核4G 套餐支持「免费升配 4核4G」（见备选 B），
> 这是阿里云轻量没有的柔性。

## 三、备选方案

### 备选 A：数据库上托管服务（我们最省心，客户最贵）

| 组件 | 规格 | 年费估算 |
|---|---|---|
| 腾讯云轻量 2核4G | 6M / 70G | ¥765（刊例） |
| TencentDB MySQL / TDSQL-C | 2核4G | ~¥2,300~3,300 |
| Redis | 1G | ~¥800 |
| COS 对象存储 | 微量 | ~¥100 |
| **合计** | | **≈ ¥4,000~5,000/年** |

- ✅ 优点：备份、主从、慢查询、故障切换由云厂商兜底 —— 我们的运维责任边界最小，
  合同里「基础设施 SLA」这一层可以干净地划走。
- ❌ 缺点：比主方案贵 **3~4 倍**；轻量服务器与 RDS 内网互通需额外配置；
  且**「客户付不付服务器钱」这个悬而未决的问题没解决之前，不该先把它锁死**。

### 备选 B：先小后大（腾讯云 2核4G 起步）

- 腾讯云轻量 2核4G 6M/70G：¥199/年（新用户），3 年期 ¥528（折合 ¥176/年）
- ✅ **支持后续免费升配 4核4G**（阿里云没有这个柔性），续费享 3.5 折
- ❌ 升配只能到 4核4G，且带宽 6M 偏小、流量包 600GB/月
- 适用：客户预算卡死，或想先上线观察 3 个月的真实负载

### 明确不推荐

| 选项 | 为什么不推荐 |
|---|---|
| **现有 `8.160.116.34`（2核1G）** | 内存 1 GB，连 MySQL + API + Worker 都塞不下。实测 API 单容器就 90 MB。它继续当边缘 + 隧道即可 |
| **校园机直接承载生产** | 合规红线：承载真实校友个人信息（姓名/地区/行业/加密联系方式）必须上云，见 `docs/DEPLOY-OPTIONS-COST.md` 第四节 |
| **8核16G / 4核16G** | 校友会场景（当前 1202 条用户量）用不上；带宽与并发不是瓶颈，钱花不到刀刃上 |
| **微信云托管** | 比自有服务器贵 8~10 倍（¥6000+/年），且不解决「服务器在谁名下」的问题 —— 见 `docs/DEPLOY-OPTIONS-COST.md` |

## 四、磁盘：70 GiB 需要精打细算

主方案的 70 GiB 系统盘是这档套餐的固定配置，装下这些后余量有限：

| 用途 | 预估占用 |
|---|---|
| 基础系统 + Docker | ~15 GB |
| 镜像（api/worker/admin-web/nginx/minio 等 7 个） | ~5 GB |
| MySQL 数据（当前 12 MB，按 5 年增长 ×50 估） | < 1 GB |
| MinIO 对象（若暂不换 OSS，图片全在内网） | 3~20 GB |
| 应用与访问日志（未接 SLS 时） | 5~15 GB |
| 本地备份（保留 30 天全量） | 5~10 GB |

**两个处理办法（推荐第 1 个）**：
1. **加一块 100~200 GB ESSD 数据盘**（约 ¥100~300/年），挂到 `/data`，
   放 DB 数据、MinIO 对象与备份 —— 干净且便宜；
2. **MinIO 直接换成阿里云 OSS**（`MINIO_*` 已有兼容开关 ✅），
   图片与附件全部出盘，服务器只剩无状态服务，日志也接 SLS/CloudMonitor 对账单。

## 五、正式发布要买/配的完整清单

机器只是其中一项。以下是**全部**必需项，缺一项就发不了正式版：

| # | 项目 | 谁负责 | 备注 |
|---|---|---|---|
| 1 | 阿里云轻量 4核8G（呼和浩特，Ubuntu 24.04） | **客户采购** | 建议在**客户主体**账号下买，账单与合同主体一致 |
| 2 | 域名（.cn / .com，企业主体实名） | **客户** | 注册商：阿里云万网（与备案接入商一致） |
| 3 | ICP 备案 | **客户**（材料我给清单） | 7~20 工作日；**必须在买机器之后**（备案要求服务器已购且有时长） |
| 4 | SSL 证书 | 技术侧 | 阿里云免费 DV 或 Let's Encrypt；需 TLS 1.2+ |
| 5 | 对象存储 OSS + CDN | 技术侧 | 替换 MinIO，图片不占服务器带宽 |
| 6 | 对象存储桶 CORS 策略 | 技术侧 | 小程序 `uploadFile`/`downloadFile` 合法域名也要配 |
| 7 | 微信侧配置 `request/uploadFile/downloadFile` 合法域名 | 技术侧（需管理员扫码） | **必须 HTTPS + 已备案域名 + 不能是 IP** |
| 8 | `AUTH_MODE` 从 `both` → `wechat` | 技术侧 | **上线前必须改**，否则公网 mock 登录后门还开着 |
| 9 | 正式版提审材料 | **客户** | 类目、隐私协议、用户信息收集清单、备案号展示 |
| 10 | 备份策略 | 技术侧 | MySQL 每日全量 + binlog，保留 30 天，异地副本 |
| 11 | 监控告警 | 技术侧 | 容器存活、磁盘、MySQL 连接数、API 错误率 → 告警到客户群 |
| 12 | 安全组 | 技术侧 | 只开 22/80/443；MySQL/Redis/MinIO **只走内网**，不对外暴露 |

## 六、上线顺序（关键路径：备案）

```
第 0 天  买服务器（4核8G）→ 域名注册+实名 → 提交 ICP 备案
         └─ 备案期间：客户继续用「离线演示版」体验（版本 0.6.0）
  +1~3天  阿里云初审 → 管局审核（7~20 工作日，省内快）
         └─ 备案期间：我在新机器上把生产栈部好、切 AUTH_MODE、配好 OSS 与监控
备案通过  DNS 解析 + 签发证书 + 配置微信合法域名 → 重传体验版
         └─ 真机验证通过 → 提审正式版
```

> ⚠️ **域名备案必须在服务器购买之后**，且多数省份要求服务器购买满 3 个月。
> 所以「买机器」这一步要**最先做**，不能等。

## 七、部署到新机器后需要调的参数（相对当前校园机配置）

| 参数 | 当前值 | 建议值 | 原因 |
|---|---|---|---|
| `innodb_buffer_pool_size` | **8 GB** | **1 GB** | 业务库只有 12 MB，8 GB 池子是纯浪费，且在 8G 机器上会挤爆内存 |
| `max_connections` | 1000 | **200** | 轻量规格下 1000 个连接纯属虚设，真到 200 时早已是应用侧问题 |
| compose 各服务 `mem_limit` | api 10G / mysql 32G / minio 16G … | 按 8G 机器重算（见 `docker-compose.prod.yml`） | 当前限额是照 300G 宿主机写的，直接搬过去会让 OOM killer 失去约束 |
| `BACKUP_DIR` / `BACKUP_RETENTION_DAYS` | — | 挂到数据盘 | 备份不能写系统盘 |

> 这些参数改动**必须配套做一次完整回归**（`infra/scripts/test-integration.sh`，24 步），
> 因为 `innodb_buffer_pool_size` 与 `max_connections` 变化会影响并发用例的表现。
