# 真机体验反馈通道（你 → 我，怎么传最省事）

> 目的：解决「问题不好用文字描述」的成本。
> 你不需要写需求文档、不需要描述复现步骤、不需要判断是哪个模块。
> **截图 + 能指哪就指哪，就够了。**

---

## 通道 A：截图 / 录屏丢目录（零开发，现在就能用）

### 怎么传

Windows 侧路径（WSL 里就是同一个目录）：

```
W:\home\kikun\MyProject\pkuim-alumni\debug\user-feedback\
```

把手机截图（`.png` / `.jpg`）或录屏（`.mp4`）直接拖进去就行，**不用改文件名**。

### 我怎么用

- 直接**看图**定位问题（截图我看得懂，不需要你描述「哪个是哪个」）
- 录屏可以逐段看，能看出「点了之后发生了什么」
- 需要清单时跑：

```bash
bash infra/scripts/collect-ui-feedback.sh list       # 看有哪些
bash infra/scripts/collect-ui-feedback.sh newest 5   # 取最近 5 条的完整路径
bash infra/scripts/collect-ui-feedback.sh mark       # 处理完归档
```

### 文件名（建议，不强制）

```
01_home_塔楼插画被裁切.png
02_directory_搜索结果太挤.png
03_me_字号和原型不一致.png
```

不按规范命名也没关系 —— 我看图不看名。

### 两条提醒

1. **截图前先退出登录态**（如果截图里出现别人的信息）。演示数据全是虚构的，
   但你的头像/昵称/手机号是真实的。
2. **录屏别超过 3 分钟** —— 超过了我需要抽帧，可能漏掉瞬间的问题。

## 通道 B：小程序内置「诊断信息」（半天工作量，一次投入长期省事）

在「我的」页加一个入口，点开显示并**一键复制**：

- 当前页面路径与 query
- 构建版本号与构建时间
- 数据模式（demo / auto）
- 登录态（是否已登录、角色）
- 微信基础库版本、屏幕尺寸
- 渲染层当前的关键数据快照（列表条数、当前 tab）

**为什么值得做**：你截图时不用再告诉我「我在哪一页」「用的哪个版本」——
这些信息自己会跟着一起来。我最怕的就是收到一张图然后要连问三句「这是哪个页面」。

## 通道 C：内置反馈工单（2~3 天工作量，真正的闭环）

后端加 `user_feedback` 表 + 上报接口 + 管理后台「反馈」列表页。

你在小程序里：

1. 点「我的 → 意见反馈」
2. 截图（`wx.chooseMedia`，直接从相册选）
3. 写一句话（可空 —— 空着我看图就行）
4. 提交

我这边：

- 登录管理后台就能看到你提交的全部反馈，**带页面路径、版本、设备、数据快照**
- 可以标注处理状态（待处理 / 已修复 / 不改）

**这条通道的价值**：它把「体验 → 发现 → 修复 → 回归」接成一条流水线，
以后每次发版都能用，不只是这次调 UI。

## 我最想要的最小信息（能做到就给，不能就算）

按「你愿意给的」排序，**给到第 1 条就够我开工**：

| 优先级 | 信息 | 为什么有用 |
|---|---|---|
| 1️⃣ | 截图 / 录屏 | 我直接看图，不用你翻译 |
| 2️⃣ | 「在哪个页面」（一句话） | 避免我猜错页 |
| 3️⃣ | 你觉得哪里不对（一句话） | 区分「布局丑」和「功能错」 |
| 4️⃣ | 期望效果（如果心里有具体参照） | 有参照我能一次改对 |
| 5️⃣ | 复现步骤 | 只在功能 bug 时才需要 |

**如果只有第 1 条，我也能开工** —— 我会拿图对照原型和代码去推。

## 一个前置条件：你得先有一个能长期打开的版本

体验版**本身没有过期时间**（7 天是二维码的寿命，不是体验版的寿命），
扫码进过一次之后还会进微信「最近使用」，以后首页下拉直接进。

所以在体验之前先做一次（**只需一次，5 分钟**）：

1. 微信公众平台 →「管理 → 版本管理」→ 找到 **0.7.0** → 「设为体验版」
2. 「管理 → 成员管理 → 体验成员」→ 添加你的微信号

之后你想体验多少次就体验多少次，不用再找我要码。

> 详细步骤见 `docs/EXPERIENCE-VERSION-GUIDE.md`。
> 如果你要看的是**还没传到平台的最新改动**（比如首页那两处调整），
> 告诉我一声，我出一个临时预览码（约 25 分钟窗口，仅开发成员可扫）——
> 但那只能应急，正式体验还是靠体验版。
